# Gaps found building Swizzy on Morgana

Found while rebuilding Swizzy (`budding-gilgamesh/swizzy`) on the published
`@studiomorgana/cli` / `sdk` 0.5.1. Each is something Morgana should do or
document.

| # | Gap | Where it bit | Workaround in Swizzy |
|---|---|---|---|
| 1 | `ctx.ai.generateText` / `agent.run` do not report token usage. | Ad debt is priced per token. | Estimate tokens as characters ÷ 4 (`server-objects/job.ts`). |
| 2 | **`/` cannot be served by a route action**, so a server-rendered home page cannot live at `/`. The host reserves `/`. | The wall (home) is server-rendered. | The wall lives at **`/wall`**. Visitors to `/` do not land on it. |
| 3 | Pages do not accept `align` (only boxes do). | Centring the console screen. | An extra `centered()` wrapper box on every page (`lib/chrome.ts`). |
| 4 | `list` does not accept `layout`; `text` does not accept `grow`. | Job list, trail, files. | **Works in 0.6** — lists take every box prop (the studio's log, files and chips are styled lists). |
| 5 | Fonts (`fonts` / `text` in config) are in 0.5.2, which is not published. | JetBrains Mono / IBM Plex Sans. | `fontFamily` stacks; they only render if installed locally. |
| 6 | Following a server object chosen at runtime is undocumented. The guide only shows fixed names (`object:board/main.…`). | Job page follows `/job/:id`. | `ctx.objects.job.get(id).on(...)` / `.watch(...)` — works per the SDK types, needs a guide section. |
| 7 | Unverified: setting a list's `data` from a server route action, and `*href` on a `link` template. | Wall job list, trail, files. | Used as documented; confirm on first run. |
| 8 | No way to run code in the cloud (tests, builds). Deployed server code is QuickJS. | Repair/feature verification. | Verify by model review for now; candidate `ctx.server.exec` (Cloudflare Sandbox). |
| 10 | `ctx.ui.login()` renders only a "Sign in" button: it creates no email/password fields, and submitting only emits `login-form.submitted` — nothing signs in. The guide implies it signs people in. | Login page did nothing. | Place `email` / `password` inputs in it; `signIn` action on `login-form.submitted` calls `ctx.auth.signIn` (`actions/client/access.ts`). |
| 11 | Placing onto a page found with `ctx.ui.pages.get(name)` does not register on the page — only the handle `pages.create` returned works. The page compiles empty. | Helpers' `place(x).on('login')`. | Helpers keep the handles they created (`@studiomorgana/helpers`). |
| 12 | The login form's built-in submit button cannot be styled — it is not an object, so no props reach it. | Unstyled "Sign in" key on a dark screen. | None yet. |
| 13 | Every form/login/signup submit dispatched `submitted` **twice**: once from the generic DOM listener (payload = the raw event) and once from the forms behaviour (payload = the values). Handlers ran twice; sign-in sent an empty request (400) then the real one. | Two sign-in calls per click. | **Fixed in source** (`sdk-compile/src/client/dom-events.ts`, ships next release). Swizzy guards on 0.5.1: act only when the payload has the values. |
| 14 | Page-load motion (`make('fade-in')`) has fixed timing: no duration, delay or repeat. Only browser `handle.animate.*` takes timing. | `animate.fadeIn(x).for('slow').whenItAppears()`. | **Fixed in 0.6:** `appear` / `leave` props (helpers `appears('rise', 500)`, `leaves('toRight')`) compile to a transition and `@starting-style` — every time it shows or is stamped, no script. |
| 15 | Core controls ship with **no base styles**: `input`, `button`, and form rows render as browser defaults. Only some kinds (select, switch…) paint from theme variables. | Unstyled fields and the white "Sign in" key. | Style every control through theme appearances; build login as a `form` with our own submit button. Fix: base styles for input/button/form that paint from `--muted`, `--border`, `--primary`. |
| 16 | A page's own props (`bg`, `pad`, `layout`, `align`) never reach `<body>` — only `theme` and `mode` do. The page stays white around a styled box. | White page around the login screen. | Paint the page with a theme (`<body>` uses `--background`); centre with a frame box. |
| 17 | `ctx.ui.theme.get()` reports `light` until `set()` is called, even on a `system` page showing dark. | Light/Dark toggle did nothing on first press. | **Fixed in 0.6:** declare `theme.mode` (`state.define('theme.mode', { keep: 'device' })`) — kept, restored onto `<body>` before paint, readable as state. |
| 18 | An object placed `hidden` at build still painted on first load — the compiler wrote `data-prop-hidden` but nothing hid it; only the runtime's `set('hidden')` did. | All three workbox views showed at once. | **Fixed in source** (`sdk-compile/src/render/html.ts`: inline `display:none`, which the runtime clears on show; 496 tests pass). Swizzy hides them on `loaded` for 0.5.1. |
| 19 | Changing a page's address after `pages.create` with `setProps({ address })` does nothing; only `page.route(address)` moves it. | `create.page('console').at('/')` landed at `/console`. | Helpers' `.at()` uses `route()`. |
| 20 | `width: 'fill'` compiles to `width:100%` **and** `flex-grow:1`, so in a column it also stretches the object to the page's full height. | The workbox and its panels ate the whole region. | Helpers' `full()` uses `'stretch'` (100% wide, no grow); `grow()` is separate. |
| 21 | Text renders as `<p>` with the browser's default 1em margins, adding space no prop asked for. | Big gap between the wordmark and its line. | **Fixed in source** (`sdk-compile/src/style/sheet.ts`: text margin 0). Swizzy resets it on load for 0.5.1. |
| 22 | Changing a **button's** look in the browser re-stamps the button's default primary style inline (orange fill, radius, padding): the runtime resolves each prop write with the kind's defaults. | Clicking a tab painted every tab orange. | **Fixed in source** (`sdk-compile/src/client/runtime.ts`: drop kind defaults on prop writes). Swizzy tabs are text objects. |
| 23 | `handle.get('value')` on an input returns the last value set from code, not what the user typed. | The form said every field was empty. | **Fixed for bound fields in 0.6:** `bind(path, { prop: 'value' })` (helpers `valueFrom`) writes the path as you type. |
| 24 | A list with a content template can't add rows in the browser: `set('data')` and state binding don't re-stamp, and `append` adds a bare `<li>` of joined values. Templated rows only render at build or server render. | Task activity and files never showed. | **Fixed in 0.6:** a list bound to a state array stamps, updates and removes rows from its template, keyed (`fill(log).from('log', 'id')`). Rows share the template's CSS (`data-tpl`); a click in a row reports the template object and `event.row`. |
| 25 | No prop for the focus outline, so a borderless textarea still gets the browser's focus ring. | The service page's writing area grew a box when you clicked in it. | **Fixed in 0.6:** `outline` prop (helpers `noOutline()`), plus `resize`, `transform`, `pointerEvents`. |
| 26 | No way to style scrollbars: scroll areas show the browser's default bar. | The workbox's inside scroll looked unfinished. | Helpers' `theme.scrollbars(...)` writes the styling into the themed page's head. Fix: a `scrollbar` prop or theme key. |
| 27 | Writing a full CSS `pad` (e.g. `'20px calc(50vw + 16px) 28px 16px'`) from the browser doesn't reach the element, though the same value compiles fine at build time. | The preview panel's split layout couldn't push the page aside. | **Avoided, not fixed:** the split is now a condition (`while('panel','open').onScreen('split')`), compiled. The runtime write path is still unexamined. |
| 28 | The studio's browser action was raw DOM: 30 `addEventListener` / `querySelector` / `el.style` / `history` / storage calls, and a 100ms tick that pushed ~8 prop writes through the style resolver. Morgana had no state-driven styles, no runtime lists, no key or file events, no address-synced state. | All of Swizzy's browser side. | **Fixed in 0.6** (PLAN-0.6.md): declared state, conditions, live lists, `key:` / `filesAdded` / `released` events, `easesHeight`. The studio's actions only write state. |
| 29 | `ctx.ui.state` re-parsed the page's JSON block on every read and re-serialised it on every commit; `setState({...})` committed once per key. | Every tick of the build. | **Fixed in 0.6:** state in memory, `setState` one commit, each changed path notifies once. |
| 30 | `pin` placement ignored its coordinates; `aspectRatio` only applied to images and video; only fields had `focus()`. | The preview panel, the hero image, focusing Approve. | **Fixed in 0.6.** |
| 9 | The guide taught the pieces but not the order to design in. | Planning Swizzy. | **Fixed:** `docs/11-designing-an-app.md` and the `AGENTS.md` template. |
